## 第 2 关：两段信号（linux-foundations）

### 题意理解

- 一批材料中**夹杂了无关文件**，要找出两段有效信号
- 两份输入由**文件名**中的 `signal-A`、`signal-B` 标识
- 对应密钥来自**清单中唯一的 `ACCESS_KEY=` 记录**——清单里含有干扰记录
- 结果 = A 段结果 + B 段结果，**A 在前、B 在后**，不能缺段、重复或增加额外字节

### 我的思路

| 提示 | 对应动作 |
| --- | --- |
| 目录可能嵌套多层；`find` 适合递归查找；管道可以把输出交给另一个命令筛选 | `find /workspace -type f` 再管道给 `grep` 筛选出带 `signal-A` / `signal-B` 的文件名 |
| 密钥清单含有干扰记录；`grep` 可以定位带特定标记的行，但整行文本未必都是密钥 | `grep -rn 'ACCESS_KEY=' /workspace`，然后**取等号右边的值**，并且要挑出唯一有效的那条 |
| 重定向中覆盖与追加有不同作用；注意程序的固定输出位置是否会被后一次执行覆盖 | 

如果 `exam` 每次都把结果写到**同一个固定路径**，那么：

```bash
/workspace/exam ...signal-A...     # 写出结果文件 R
/workspace/exam ...signal-B...     # 又写到同一个 R，A 的结果被冲掉了
```

第一次的结果**在第二次执行的那一刻就没了**。所以必须先把 A 的结果搬走，再处理 B：

```bash
# 1. 定位材料（注意嵌套目录和干扰文件）
find /workspace -type f
find /workspace -type f -name '*signal-A*'
find /workspace -type f -name '*signal-B*'

# 2. 从清单里找唯一的 ACCESS_KEY
grep -rn 'ACCESS_KEY=' /workspace

# 3. 先处理 A，把结果搬到别处
/workspace/exam <A段输入> <KEY> <OUT>
cp <OUT> /tmp/partA

# 4. 再处理 B
/workspace/exam <B段输入> <KEY> <OUT>

# 5. A 在前、B 在后拼接
cat /tmp/partA <OUT> > /workspace/flag
```

## 第 3 关：读日志并修复输入（linux-foundations）

### 题意理解

- 原始输入 `/workspace/input.txt`：**ASCII 文本，带一个结尾换行**；密钥 `/workspace/key.txt`
- 处理程序 `/workspace/exam`，诊断日志在 `/var/log/ncuscc/exam.log`
- **允许的修改仅限**：在**最后一行文字与结尾换行之间**插入 ASCII 空格；其他字节必须保留
- 且**新增空格数最少**
- 提交 `/workspace/flag`（用修复后输入跑出来的结果），**不需要**提交修改后的输入文件

### 我的思路

| 提示 | 对应动作 |
| --- | --- |
| 退出状态和日志提供不同的信息；后续命令会改变 `$?` | 先看退出码判断成功与否，**再**看日志找失败原因。`$?` 只在紧跟命令之后有效 |
| 诊断涉及长度时，注意程序比较的是字节数还是可见字符数，结尾换行也占用字节 | 用 `wc -c`（字节）而不是 `wc -m`（字符）|
| 结合程序规则计算最小改动，避免编辑器额外修改换行或其他内容 | 用 `head -c` + `printf` 精确构造，**不要用 vi/nano 打开再保存** |

### 实现要点

```bash
# 1. 先看程序接口
/workspace/exam --help

# 2. 复现失败，紧接着看退出码
/workspace/exam <input.txt> <key.txt> <OUT>
echo $?

# 3. 看诊断日志，找出失败原因
cat /var/log/ncuscc/exam.log

# 4. 量当前输入的字节数
wc -c /workspace/input.txt

# 5. 设日志要求长度为 NEED，当前为 HAVE，则要补 PAD = NEED - HAVE 个空格
HAVE=$(wc -c < /workspace/input.txt)
NEED=...                                  # 由日志给出
PAD=$(( NEED - HAVE ))

# 6. 精确构造：去掉原结尾换行 → 补空格 → 补回换行
head -c $(( HAVE - 1 )) /workspace/input.txt > /tmp/fixed.txt
printf '%*s' "$PAD" '' >> /tmp/fixed.txt
printf '\n' >> /tmp/fixed.txt

# 7. 校验长度正好等于 NEED
wc -c /tmp/fixed.txt

# 8. 用修好的输入跑，
/workspace/exam /tmp/fixed.txt /workspace/key.txt <OUT>
cp <OUT> /workspace/flag
```

### 为什么必须用 `head -c` + `printf`，不能用编辑器

vi / nano / 记事本在保存时可能：

- 把结尾换行改掉，或自动补一个
- 把行尾的空格"顺手"删掉（很多编辑器会自动清理行尾空白）
- 改变编码或换行符（`\n` → `\r\n`）
`head -c` / `printf` 是**只动指定的字节，其余一个不碰**。
原文结尾是：
```
...最后一行文字\n
```

插入后变成：

```
...最后一行文字<spaces>\n
```

这样同时满足两个条件：
- 所有原有字节的**内容和顺序完全保留**（只是中间多了空格）
- 结尾换行仍在最后一个字节

# 二、Git 基础（git-foundation）

## 题意理解

这一关不是"写代码"，而是**在服务器上把一个目录变成符合要求的 Git 仓库**。

初始状态：`/workspace/repo/` 是一个普通目录，里面只有 `notes.txt`，**还不是 Git 仓库**。

验收条件（题面原文）：

> 独立仓库，HEAD 在 main；init 路径没有提交/暂存内容；clone 路径保留基线，且工作区干净。

题面给出**两条互斥的路径**，任选其一：

| 路径 | 做法 | 验收要求 |
| --- | --- | --- |
| **init 路径** | 在 `/workspace/repo` 执行 `git init -b main`，保持 `notes.txt` 原样且未暂存 | 没有提交、没有暂存内容 |
| **clone 路径** | 删除练习目录后，从 `/opt/recruitment/git-seed` 克隆到 `/workspace/repo` | 保留基线历史，且工作区干净 |

## 我的思路

**关键判断**：这两条路径的验收标准**互相冲突**，所以必须先读懂条件再动手。

- init 路径要的是"**什么都没有**"——`git log` 报错是正确的；
- clone 路径要的是"**有历史且干净**"——`git log` 必须能列出提交。

如果没读清楚就凭直觉去 `git add . && git commit -m "init"`，看起来"很规范"，实际上同时违反了 init 路径的"没有提交/暂存内容"，是一条必挂的路。

所以选 **init 路径**：命令最少、副作用最小，一条 `git init -b main` 就满足全部条件。

## 实现要点

```bash
cd /workspace/repo
git init -b main
git status --short --branch
```

预期输出：

```
## No commits yet on main
?? notes.txt
```

`git init -b main` ：在目录下创建 `.git/` 子目录（对象库、引用、索引、配置），并把初始分支名设为 `main`。

：**"HEAD 在 main"和"存在 main 分支"是两回事**。

- `git init -b main` 之后，`.git/HEAD` 的内容是 `ref: refs/heads/main`
- 但 `.git/refs/heads/main` **这个文件还不存在**，因为还没有任何提交
- 这就是 Git 里的 **unborn branch（未出生分支）**状态：HEAD 已经指向了一个"还不存在的分支名"

这也解释了为什么题目要求的是「**HEAD 在 main**」而不是「**有 main 分支**」——因为一个刚初始化、零提交的仓库里根本不可能有分支，只有 HEAD 的指向。

同理，`git log` 此时报 `fatal: your current branch 'main' does not have any commits yet` **不是错误，而是这个状态的必然结果**。提示面板也专门说明了这一点："init 路径尚无提交，git log 报没有提交是正常现象"。

## 运行结果与验证

| 检查项 | 命令 | 结果 |
| --- | --- | --- |
| 是否已是仓库 | `git status --short --branch` | `## No commits yet on main` ✅ |
| 暂存区为空 | `git diff --cached --name-only` | 无输出 ✅ |
| 提交历史为空 | `git log --oneline` | 报"没有提交"，符合 init 路径预期 ✅ |
| 工作区文件未改动 | `git status --short` | 只有 `?? notes.txt`（未跟踪，非暂存）✅ |
| HEAD 指向 | `.git/HEAD` 内容 | `ref: refs/heads/main` ✅ |

## 遇到的坑

**1. 把普通目录当成 Git 仓库。**
- 现象：`cd repo` 之后执行 `git status --short --branch`，报
  `fatal: not a git repository (or any parent up to mount point /)`
- 原因：`/workspace/repo` 只是一个普通目录，`.git/` 还不存在，Git 向上找不到仓库边界就报错。
- 解决：先 `git init -b main` 把它变成仓库。这个报错本质上是**"这个目录还没被 Git 管起来"**，不是权限问题也不是路径问题。

**2. 误以为提示是工作区里的文件。**
- 现象：`cat hints.md` 报 `No such file or directory`。
- 原因：这一关的提示**只在页面右侧面板里**，工作区只有 `README.md` 和 `repo/`。前面几关工作区里确实有 `hints.md`，形成了思维定式。
- 教训：**每关的资源布局不一定相同，先 `ls` 看清楚，别假设。**

- **命令**：`git init -b main`（`-b`

# 三、C/C++ 建造与运行（cpp-build-run）

## 题意理解

这是 C/C++ 方向的**入门关**，题面自己说明了它的重点：

> 重点是把「编辑 → 编译 → 运行 → 提交」的闭环走通，并严格按输出契约输出。

**输入**（标准输入）：

- 第一行：整数 `n`（1 ≤ n ≤ 10000）
- 第二行：`n` 个整数，空格分隔，每个在 `[-1000, 1000]`

**输出**（标准输出，**恰好 4 行**，`=` 两边不要有空格）：

```
count=<n>
sum=<所有读数之和>
min=<最小读数>
max=<最大读数>
```

程序必须以**退出码 0** 结束。

**提交要求**：构建入口必须是**根目录下恰好一个** `main.c` 或 `main.cpp`。两个同时存在、或一个都没有，都会得到 `SOURCE_MISSING`。

## 我的思路

这题本身不难（就是一次遍历统计），它真正考的是**工程习惯**，所以我把思路分成两层：

**第一层：算法层面**

四个统计量（count / sum / min / max）全部可以在**一次遍历**中更新完：

| 统计量 | 更新方式 |
| --- | --- |
| `count` | 每成功读入一个就 +1 |
| `sum` | 每读入一个就累加 |
| `min` / `max` | 用**第一个读到的数**初始化，之后每次比较更新 |

时间 O(n)、空间 O(1)，n ≤ 10000 完全够用，`sum` 在 32 位 int 范围内，不需要 64 位。

**第二层：契约层面**

题面用了大量篇幅强调"输出恰好 4 行""`=` 两边不要有空格""退出码 0"，这不是啰嗦——**这题的分不在算法上，全在契约上**。所以我的做法是：先让样例替我验证，再谈代码写得漂不漂亮。

## 实现要点（C 版）

我选择用 C 完成，先按题面把入口整理清楚：

```bash
cd /workspace
cp c/main.c main.c        # 把 C 模板复制到根目录当入口
rm -f main.cpp            # 根目录只能留一个入口文件
gcc -std=c11 -Wall -Wextra -o main main.c
```

实现：

```c
#include <stdio.h>

int main(void)
{
    int n;
    int i;
    int count = 0;
    int sum = 0;
    int min = 0, max = 0;
    int have = 0;

    if (scanf("%d", &n) != 1) {
        return 1;
    }

    for (i = 0; i < n; ++i) {
        int v;
        if (scanf("%d", &v) != 1) {
            return 1;
        }

        /* 关键：min/max 用第一个读到的数初始化，不能用 0 */
        if (!have) {
            min = v;
            max = v;
            have = 1;
        } else {
            if (v < min) min = v;
            if (v > max) max = v;
        }

        sum += v;
        count += 1;
    }

    printf("count=%d\n", count);
    printf("sum=%d\n", sum);
    printf("min=%d\n", min);
    printf("max=%d\n", max);

    return 0;
}
```

**三个必须做对的地方：**

1. **min/max 用第一个数初始化，不能用 0。**
   读数在 `[-1000, 1000]`，如果全为正数（例如 `3 4 5`），用 0 初始化的 `min` 会输出 `min=0` —— 一个根本没出现过的值。这是本题最经典的错。
   我用了 `have` 标志位而不是"用第一个数初始化再循环剩余"，这样 n=1 时也不用特判，代码只有一条路径。

2. **前缀是 `=` 不是 `:`。**
   `count=5` 而不是 `count: 5`，`=` 两边也没有空格。

3. **恰好 4 行，且每行都以 `\n` 结尾。**
   不能多一行空行，也不能少最后一个换行。用 `printf("...\n")` 就是最省心的写法。

## 遇到的坑

**1. `SOURCE_MISSING` —— 根目录同时存在两个入口文件。**

- 现象：工作区里 `main.cpp`（C++ 模板）和 `c/main.c`（C 模板）一开始都在。如果只是"把 `c/main.c` 复制成 `main.c`"却忘了删 `main.cpp`，根目录就有两个入口。
- 原因：判题要求**根目录恰好一个** `main.c` 或 `main.cpp`，多于一个无法确定用哪个。
- 解决：`rm -f main.cpp`，保证根目录只有一个。

**2. min 初始化为 0 导致全正数输入输出错误。**

- 现象：输入 `3 4 5` 时输出 `min=0`，而 0 从没出现过。
- 原因：`min` 的初始值必须是**数据里真实存在的值**，而 0 只是 int 的默认值。读数范围含负数，所以"用 0 当上界/下界"在两侧都不安全。

# 四、C++ 程序结构（cpp-program-structure）

## 题意理解

- **输入**：第一行是记录数 n（1 ≤ n ≤ 1000）；随后 n 行，每行三个字段 `<type> <status> <hours>`。`type` 只能是 printer / scanner / router / server，`status` 只能是 ok / repair，`hours` 是 0..100000 的整数。
- **输出**：固定 5 行 —— 前 4 行是「类型 记录数 总小时数」，顺序**固定**为 printer、scanner、router、server；第 5 行是 `busiest <type>`。
- **三个容易漏掉的约束**：
  1. 某类**一条记录都没有也必须输出** `0 0`；
  2. 总小时数**并列时**，取固定顺序中**更靠前**的类型；
  3. 退出码必须为 0。
- **规模**：n ≤ 1000，总小时数最多 10^8，`int` 足够。**这道题没有算法难度**，考的是把输入正确归类、把输出严格对齐。

## 我的思路

**第一反应**：用一个 `map<string, ...>` 或 4 个 `if-else` 分支去统计。但这样会带出两个额外麻烦：输出时要按固定顺序遍历（map 是按字典序排的，printer/scanner/router/server 恰好不是题目顺序），以及缺失的类型要单独补零。

**最终做法**：把「类型名 → 固定输出顺序」直接做成**数组下标**。

```c
static const char *const kTypeNames[4] = {"printer", "scanner", "router", "server"};
struct type_total totals[4];   /* 下标 0..3 与固定输出顺序一一对应 */
```

一个映射同时消灭三个约束：

| 题目要求 | 常规写法的麻烦 | 用下标后 |
| --- | --- | --- |
| 四行固定顺序输出 | 要额外排序 | 数组顺序就是输出顺序 |
| 没记录也要输出 `0 0` | 要特判补零 | 初始化为 0，天然满足 |
| 并列取靠前 | `>=` 写反就错 | 从 0 扫到 3，只在严格大于时更新 |

复杂度：**O(n) 时间、O(1) 额外空间**（固定 4 个计数器，与 n 无关）。

## 实现要点

```c
/* 按完整内容比较类型名，返回 0..3 */
static int type_index(const char *type)
{
    int i;
    for (i = 0; i < TYPE_COUNT; ++i) {
        if (strcmp(type, kTypeNames[i]) == 0) {   /* 必须整体比较，不能只比首字符 */
            return i;
        }
    }
    return -1;
}

/* 并列时保留更小的下标，也就是固定顺序里更靠前的类型 */
for (i = 1; i < TYPE_COUNT; ++i) {
    if (totals[i].hours > totals[busiest].hours) {   /* 必须是 >，写成 >= 就错 */
        busiest = i;
    }
}
```

其他要点：

- 用 `struct type_total { int count; int hours; }` 把「记录数」和「总小时数」打包，避免两个平行数组对错下标。
- `status` 字段公开输出用不到，但**必须照常读进来**，否则输入指针错位、后面全部读乱。
- `scanf("%15s %15s %d", ...)` 里的宽度上限防止类型名超长写爆 `char[16]`。

## 遇到的坑

**1. 并列方向写反了（最典型）**
- 现象：样例 2 输出 `busiest server`，正解是 `busiest printer`。
- 原因：第一版写的是 `>=`，思路是"相等也更新一下更保险"。但 `>=` 的真实语义是"并列时取**靠后**的"，与题目要求正好相反。
- 解决：改成严格 `>`。因为扫描方向本来就是从靠前到靠后，只有严格更大才更新，第一个最大值天然被保留。

**2. 差点只比较首字符**
- `scanner` 和 `server` 首字母都是 `s`，若用 `type[0]` 判断会把两类合并，计数和小时数全错。
- 解决：用 `strcmp` 整体比较。只有 4 个候选、字符串很短，这点开销可忽略。
- 值得一提的是：样例 1 里这两类都有记录，所以这个错误**跑一次样例就会暴露**——但如果不跑样例只靠肉眼看代码，很容易放过去。

**3. 想过特判"某类没有记录"**
- 最初打算"没有的类型跳过不输出，反正提交器只比对有内容的行"，后来发现题目白纸黑字写着**即使没有记录也必须输出**。
- 改成固定数组后这个问题自动消失——每次都无条件打印 4 行。
