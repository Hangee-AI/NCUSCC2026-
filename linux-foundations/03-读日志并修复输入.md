# 第 3 关：读日志并修复输入（linux-foundations）

### 题意理解

- 原始输入 `/workspace/input.txt`：**ASCII 文本，带一个结尾换行**；密钥 `/workspace/key.txt`
- 处理程序 `/workspace/exam`，诊断日志在 `/var/log/ncuscc/exam.log`
- **允许的修改仅限**：在**最后一行文字与结尾换行之间**插入 ASCII 空格；其他字节必须保留
- 且**新增空格数最少**
- 提交 `/workspace/flag`（用修复后输入跑出来的结果），**不需要**提交修改后的输入文件

### 我的思路

| 提示 | 对应动作 |
| --- | --- |
| 退出状态和日志提供不同的信息；后续命令会改变 `$?` | 先看退出码判断成功与否，**再**看日志找失败原因。`$?` 只在紧跟命令之后有效 |
| 诊断涉及长度时，注意程序比较的是字节数还是可见字符数，结尾换行也占用字节 | 用 `wc -c`（字节）而不是 `wc -m`（字符）|
| 结合程序规则计算最小改动，避免编辑器额外修改换行或其他内容 | 用 `head -c` + `printf` 精确构造，**不要用 vi/nano 打开再保存** |

### 实现要点

```bash
# 1. 先看程序接口
/workspace/exam --help

# 2. 复现失败，紧接着看退出码
/workspace/exam <input.txt> <key.txt> <OUT>
echo $?

# 3. 看诊断日志，找出失败原因
cat /var/log/ncuscc/exam.log

# 4. 量当前输入的字节数
wc -c /workspace/input.txt

# 5. 设日志要求长度为 NEED，当前为 HAVE，则要补 PAD = NEED - HAVE 个空格
HAVE=$(wc -c < /workspace/input.txt)
NEED=...                                  # 由日志给出
PAD=$(( NEED - HAVE ))

# 6. 精确构造：去掉原结尾换行 → 补空格 → 补回换行
head -c $(( HAVE - 1 )) /workspace/input.txt > /tmp/fixed.txt
printf '%*s' "$PAD" '' >> /tmp/fixed.txt
printf '\n' >> /tmp/fixed.txt

# 7. 校验长度正好等于 NEED
wc -c /tmp/fixed.txt

# 8. 用修好的输入跑，
/workspace/exam /tmp/fixed.txt /workspace/key.txt <OUT>
cp <OUT> /workspace/flag
```

### 为什么必须用 `head -c` + `printf`，不能用编辑器

vi / nano / 记事本在保存时可能：

- 把结尾换行改掉，或自动补一个
- 把行尾的空格"顺手"删掉（很多编辑器会自动清理行尾空白）
- 改变编码或换行符（`\n` → `\r\n`）
`head -c` / `printf` 是**只动指定的字节，其余一个不碰**。
原文结尾是：
```
...最后一行文字\n
```

插入后变成：

```
...最后一行文字<spaces>\n
```

这样同时满足两个条件：
- 所有原有字节的**内容和顺序完全保留**（只是中间多了空格）
- 结尾换行仍在最后一个字节
