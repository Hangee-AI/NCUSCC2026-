## 题意理解

这一关不是"写代码"，而是**在服务器上把一个目录变成符合要求的 Git 仓库**。

初始状态：`/workspace/repo/` 是一个普通目录，里面只有 `notes.txt`，**还不是 Git 仓库**。

验收条件（题面原文）：

> 独立仓库，HEAD 在 main；init 路径没有提交/暂存内容；clone 路径保留基线，且工作区干净。

题面给出**两条互斥的路径**，任选其一：

| 路径 | 做法 | 验收要求 |
| --- | --- | --- |
| **init 路径** | 在 `/workspace/repo` 执行 `git init -b main`，保持 `notes.txt` 原样且未暂存 | 没有提交、没有暂存内容 |
| **clone 路径** | 删除练习目录后，从 `/opt/recruitment/git-seed` 克隆到 `/workspace/repo` | 保留基线历史，且工作区干净 |

## 我的思路

**关键判断**：这两条路径的验收标准**互相冲突**，所以必须先读懂条件再动手。

- init 路径要的是"**什么都没有**"——`git log` 报错是正确的；
- clone 路径要的是"**有历史且干净**"——`git log` 必须能列出提交。

如果没读清楚就凭直觉去 `git add . && git commit -m "init"`，看起来"很规范"，实际上同时违反了 init 路径的"没有提交/暂存内容"，是一条必挂的路。

所以选 **init 路径**：命令最少、副作用最小，一条 `git init -b main` 就满足全部条件。

## 实现要点

```bash
cd /workspace/repo
git init -b main
git status --short --branch
```

预期输出：

```
## No commits yet on main
?? notes.txt
```

`git init -b main` ：在目录下创建 `.git/` 子目录（对象库、引用、索引、配置），并把初始分支名设为 `main`。

：**"HEAD 在 main"和"存在 main 分支"是两回事**。

- `git init -b main` 之后，`.git/HEAD` 的内容是 `ref: refs/heads/main`
- 但 `.git/refs/heads/main` **这个文件还不存在**，因为还没有任何提交
- 这就是 Git 里的 **unborn branch（未出生分支）**状态：HEAD 已经指向了一个"还不存在的分支名"

这也解释了为什么题目要求的是「**HEAD 在 main**」而不是「**有 main 分支**」——因为一个刚初始化、零提交的仓库里根本不可能有分支，只有 HEAD 的指向。

同理，`git log` 此时报 `fatal: your current branch 'main' does not have any commits yet` **不是错误，而是这个状态的必然结果**。提示面板也专门说明了这一点："init 路径尚无提交，git log 报没有提交是正常现象"。

## 运行结果与验证

| 检查项 | 命令 | 结果 |
| --- | --- | --- |
| 是否已是仓库 | `git status --short --branch` | `## No commits yet on main` ✅ |
| 暂存区为空 | `git diff --cached --name-only` | 无输出 ✅ |
| 提交历史为空 | `git log --oneline` | 报"没有提交"，符合 init 路径预期 ✅ |
| 工作区文件未改动 | `git status --short` | 只有 `?? notes.txt`（未跟踪，非暂存）✅ |
| HEAD 指向 | `.git/HEAD` 内容 | `ref: refs/heads/main` ✅ |

## 遇到的坑

**1. 把普通目录当成 Git 仓库。**
- 现象：`cd repo` 之后执行 `git status --short --branch`，报
  `fatal: not a git repository (or any parent up to mount point /)`
- 原因：`/workspace/repo` 只是一个普通目录，`.git/` 还不存在，Git 向上找不到仓库边界就报错。
- 解决：先 `git init -b main` 把它变成仓库。这个报错本质上是**"这个目录还没被 Git 管起来"**，不是权限问题也不是路径问题。

**2. 误以为提示是工作区里的文件。**
- 现象：`cat hints.md` 报 `No such file or directory`。
- 原因：这一关的提示**只在页面右侧面板里**，工作区只有 `README.md` 和 `repo/`。前面几关工作区里确实有 `hints.md`，形成了思维定式。
- 教训：**每关的资源布局不一定相同，先 `ls` 看清楚，别假设。**
