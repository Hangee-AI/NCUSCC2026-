## 题意理解

- **输入**：第一行是记录数 n（1 ≤ n ≤ 1000）；随后 n 行，每行三个字段 `<type> <status> <hours>`。`type` 只能是 printer / scanner / router / server，`status` 只能是 ok / repair，`hours` 是 0..100000 的整数。
- **输出**：固定 5 行 —— 前 4 行是「类型 记录数 总小时数」，顺序**固定**为 printer、scanner、router、server；第 5 行是 `busiest <type>`。
- **三个容易漏掉的约束**：
  1. 某类**一条记录都没有也必须输出** `0 0`；
  2. 总小时数**并列时**，取固定顺序中**更靠前**的类型；
  3. 退出码必须为 0。
- **规模**：n ≤ 1000，总小时数最多 10^8，`int` 足够。**这道题没有算法难度**，考的是把输入正确归类、把输出严格对齐。

## 我的思路

**第一反应**：用一个 `map<string, ...>` 或 4 个 `if-else` 分支去统计。但这样会带出两个额外麻烦：输出时要按固定顺序遍历（map 是按字典序排的，printer/scanner/router/server 恰好不是题目顺序），以及缺失的类型要单独补零。

**最终做法**：把「类型名 → 固定输出顺序」直接做成**数组下标**。

```c
static const char *const kTypeNames[4] = {"printer", "scanner", "router", "server"};
struct type_total totals[4];   /* 下标 0..3 与固定输出顺序一一对应 */
```

一个映射同时消灭三个约束：

| 题目要求 | 常规写法的麻烦 | 用下标后 |
| --- | --- | --- |
| 四行固定顺序输出 | 要额外排序 | 数组顺序就是输出顺序 |
| 没记录也要输出 `0 0` | 要特判补零 | 初始化为 0，天然满足 |
| 并列取靠前 | `>=` 写反就错 | 从 0 扫到 3，只在严格大于时更新 |

复杂度：**O(n) 时间、O(1) 额外空间**（固定 4 个计数器，与 n 无关）。

## 实现要点
```c
/* 按完整内容比较类型名，返回 0..3 */
static int type_index(const char *type)
{
    int i;
    for (i = 0; i < TYPE_COUNT; ++i) {
        if (strcmp(type, kTypeNames[i]) == 0) {   /* 必须整体比较，不能只比首字符 */
            return i;
        }
    }
    return -1;
}

/* 并列时保留更小的下标，也就是固定顺序里更靠前的类型 */
for (i = 1; i < TYPE_COUNT; ++i) {
    if (totals[i].hours > totals[busiest].hours) {   /* 必须是 >，写成 >= 就错 */
        busiest = i;
    }
}
```

## 遇到的坑
**1. 并列方向写反了**
- 现象：样例 2 输出 `busiest server`，正解是 `busiest printer`。
- 原因：第一版写的是 `>=`，思路是"相等也更新一下更保险"。但 `>=` 的真实语义是"并列时取**靠后**的"，与题目要求正好相反。
- 解决：改成严格 `>`。因为扫描方向本来就是从靠前到靠后，只有严格更大才更新，第一个最大值天然被保留。

**2. 差点只比较首字符**
- `scanner` 和 `server` 首字母都是 `s`，若用 `type[0]` 判断会把两类合并，计数和小时数全错。
- 解决：用 `strcmp` 整体比较。只有 4 个候选、字符串很短，这点开销可忽略。
- 值得一提的是：样例 1 里这两类都有记录，所以这个错误**跑一次样例就会暴露**——但如果不跑样例只靠肉眼看代码，很容易放过去。
